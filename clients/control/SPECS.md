# spacectl 1.0 原生 CLI 规格

2026-11-19 修正：发行包只提供 `space-ops/SKILL.md` 技能正文，不包含 references 或 agents 附属文件，安装检查必须覆盖真实技能包。命令组的用途由命令元数据声明，`--help` 和 `schema GROUP --brief` 从实际命令树展示直属命令及后续发现路径，不展开所有后代或类型。方法地图显式返回 `credentialTypes`、`scopes`、`idempotencyMode` 与 `confirmationRequired`，不要求调用方从描述文字推断身份和写入条件。
有限选项形式的字符串 pattern（如 `authored|synced`）在 CLI 契约中同时生成精确 enum，匹配服务端整值校验；不收窄一般正则或改动原始 OpenAPI。
本地输入校验返回有界 `error.violations[{field,code}]`，字段只由契约生成；动态 map 键以 `*` 代替，不回显用户值或秘密。CLI、MCP 和批量共用同一预校验。动态字段与数组中的秘密值也必须通过文件/stdin 输入，预演始终脱敏。分页只有 null 游标证明结束；错误类型、空字符串或循环游标均报错，不能误报完整读取。

当前 CLI 用法以 [USAGE.md](USAGE.md) 和实际 help/schema 为准。

2026-10-23 全新项目约束：不维护旧解析器的字面值转换、短选项、重复 profile 覆盖及诊断排版兼容。help/version、布尔/数值/Path 转换和选项继承采用 Aesh 原生模型；短版本选项为 -v，Path 按 Aesh 上下文解析。重复标量选项仍拒绝，避免身份或执行意图歧义。错误输出保留安全分类、退出码与当前帮助入口，不回显解析器原始异常。技能安装只处理发行包列出的当前受管技能；同一技能升级时按所有权清单清理过期受管文件，不扫描、迁移或备份其他技能；未知写入恢复与凭据安全约束继续保留。最终制品须进行真实 Pi Agent 验证并冻结命令、模型事件、HTTP 与实际 usage。

2026-10-22 执行与成本收敛：技能按本次专项 profile 和完成阶段选择分支，恢复绑定原 profile/意图，缺凭据仅诊断指定来源后报告受阻。给定连接时直接执行业务请求，不固定预先执行版本、配置和身份三次发现。仅在参数或路径未明时查局部契约；预演与结果核验保留，已充分证明的阶段不重复查询。导入按原作业→目标 Release→目标正文核验，历史模型失败和 token 负结果继续保留。
任务指定本地写入意图 ID 或前缀时，技能通过 --invocation-id 传递；服务端 Idempotency-Key 不替代本地 journal 身份。该指导不删除 CLI 默认派生 ID 或自定义服务端键的已有能力。
指定来源的诊断范围适用于所有业务分支，不能仅在 credential_missing 参考里约束。凭据诊断使用所选 profile 的 get/inspect/auth status，普通任务不枚举环境变量名称或探索其他 profile；用户明确要求的配置管理仍按其授权范围执行。

2026-10-22 跨端修复补充：`config get` 只返回全局 `--profile` 选定的非秘密配置，`config inspect` 只检查该 profile 声明的凭据来源。环境来源只报告该变量的 present/missing；系统凭据库不隐式解锁或读取，报告 not_checked。两者不发 HTTP、不触发后台更新、不枚举其他来源；本地来源存在不证明远程认证或授权。`config list` 保留全列表语义。
`schema` 同时发现 HTTP 方法、类型与本地助手，使用实际 Aesh 命令模型 投影 CLI 选项、位置参数、输入分工、互斥约束、输出形态和当前可执行例子；HTTP 参数/类型仍使用同一生成契约。助手不维护第二份参数表，查询不创建凭据或回执；类型引用继续有界展开。`pages +inspect` 读取 `/content` 的正文快照与同次强 ETag；完整详情 get 不再作为新编辑基线。输入错误的 schema 提示依据当前实际操作，正文助手不得误指完整详情 get；本地拒绝仍先于凭据和 HTTP。新 CLI/MCP/+batch 的 editPage 必须明确 intent=draft_only 或 hotfix，省略与 null 在共享 catalog 本地拒绝；枚举与服务器执行约束来自当前契约。HTTP 保留旧消费者的省略/null 兼容分支，新入口不进入该分支。意图纳入原请求与幂等指纹，跨模式拒绝没有业务效果。
批量读使用显式只读的 POST 契约，不因 HTTP 动词误判为写入；1..100 个 ID、重复/游标互斥、响应上限按后端契约校验。summary 不含正文基线；content 结果包含逐页快照和 ETag，逐项不可读与不存在统一 not_found。domain 批量 publish/unpublish 是同空间一次事务及至多一次发版，不由并行单页调用冒充。通用 +batch 保留逐项 httpStatus/state/replayed，汇总明确统计已结束的请求调用，不证明异步作业或站点交付完成。
只读等待必须显式指定原 job 或原 delivery 目标，设定总时限、轮询间隔与尝试上限。只轮询，不重新提交、approve、promote或取消后台业务；预算耗尽返回最后状态并明确未完成。job 的 terminal 与 outcome、live Release 和站点 delivery 分开判定，不改既有 unknown/回执恢复语义。

管理技能采用单一中文 SKILL.md，按原则、概念和 CLI 工程事实组织，以平台专家讲解的短原则句保留精简决策。导航列真实空格执行入口，以方法 schema 的 cli.command 为准，点分 schema 与执行命令通过一个真实示例区分；只查询缺失信息的最近入口，不固定重复根目录或身份发现。原则解释操作范围，概念明确工作内容/进版候选/冻结快照/读者交付等边界，工程事实保留正文基线、预演、恢复和完成判据；不复制全部参数、枚举、资源 ID 或本次运行记录，不依赖其他技能内容文件。未知语法查询当前 help/schema，运行事实保存在任务目录。build 已按 outcome 自动晋升，修正 held 后的新尝试使用新意图。改写须在 Pi 中对比冻结旧技能、新技能与无技能，固定模型、场景与工具，保存真实业务后验和实际 usage。
字段投影的共用说明不得示范目标响应不存在的字段；字段名按方法响应 schema 选择，分页保留 nextCursor。技能字符缩减不等于实际 token 收益，行为对照保留失败、边界阻断和基础设施错误，并分别归因。

2026-10-22 审查修复：MCP 写方法必须提供 invocationId；独立新意图使用新 ID，恢复沿用原 ID、请求和键。MCP 和批量结果公开 state、replayed，普通 CLI 在 stderr 明示历史回执；重放不证明当前资源状态。失败输出在已尝试但未确认的写入上保留 state=unknown。
错误保留经过校验的 Retry-After（秒数或 HTTP 日期）与有界 violations。字段路径须来自当前输入契约，动态 map 键与任意远端错误文本不回显；未知校验码归一为 invalid。明确拒绝的回执保留安全的字段错误，恢复读取时仍可定位修正。
editPage 在 authored 空间保存工作稿，在 synced 空间执行热修、晋升 live 并应用保留策略；站点交付另行核验。两种模式统一要求 --yes / confirm，避免本地预演为判断模式访问业务接口。仅保存草稿的授权不适用于 synced 热修。help、schema 和内容技能必须说明此差异。
更新测试的当前版本、兼容新版本和跨主版本从 BuildInfo.VERSION 派生。技能安装支持只读 --check，核对发行包中的全部受管文件，漂移使检查失败；正常安装后再次核对。完整接口覆盖以生成清单为准。

失败指导：HTTP 错误按已确认拒绝与结果未决区分。408、429、409 idempotency_request_in_progress 和 5xx 不报告业务已拒绝；写入先查询回执与当前事实，有键恢复沿用原请求和原键，无键未知写入停止重放。明确拒绝提示修正或停止，不建议直接 resume。凭据类型不匹配时列出方法接受的类型并提示选择对应 profile。
`+receipt` 与 `+resume` 只在已选 profile 查找原回执。缺失诊断显示这个非秘密 profile，并提示使用原回执对应的同一 profile、保留原 ID；不扫描其他 profile、不回显原请求，不因缺失创建 journal 或读取凭据。正确 profile 的原请求、原键及历史回执语义保持不变。
技能按用户任务路由到内容、交付、访问和恢复，复用同版本已读契约。认证只使用指定来源；正文与 ETag 来自同次读取；JSON/逐页 NDJSON 分别解析。发布与导入按实际 outcome 推进，完成条件只覆盖用户要求的阶段。CLI 缺凭据提示配置的来源，缺 scope 提示契约要求，远程来源不可达不推断具体根因；提示不回显秘密或服务端原文。

本规格定义原生 Control CLI 的能力与边界；接口以生成契约及 help/schema 为准。
目标：可预测性、纵深防御、上下文效率；使用实际命令模型、按职责组织、代码精炼。

CLI/MCP/batch 的选项适配、类型化结果和执行元数据共用同一原生调用入口；命令层只负责各自的输入名称与输出信封。嵌入式调用直接消费共用输出层脱敏后的 JsonNode，不再用内存 stdout 作内部协议后重复解析。schema brief 在完整投影之后统一裁剪 CLI 展示元数据，方法、类型和本地助手走同一路径。代码精简保留原始语义、校验和恢复顺序，以同一格式化后的手写源码净减少量及全部既有场景验证，不以删测试或转移代码计收益。

`schema METHOD_OR_TYPE --brief` 从同一契约和实际 Aesh 命令模型 输出单行 JSON；默认 schema 输出完整的原生契约与当前 CLI 模型。brief 仅省略公共可选选项说明（profile、format、file-root、timeout、help、version）、重复的 CLI description、空 CLI 集合和自指 schema 示例；保留类型、必填性、枚举、边界、scope、输入分工、执行约束、输出与完成语义。公共选项按当前 --help 查询；类型及 --resolve-refs 沿用同一有界展开，不另建字段摘要或缓存。技能的方法发现优先 brief；未知类型按引用查询，已有契约足够时直接执行。真实 Pi 对照冻结旧技能、新技能与无技能，实际调用正确性及完整任务 token 共同决定收益，字符缩减不作为 token 验收。
调用期间只保留当前请求所需状态。command 仅适配 CLI/MCP/批量与组合本地命令；execution 通过 ControlCall 承载原生请求校验、执行、输出与恢复，不依赖 parser、MCP 或 update。更新仅依赖必要共享能力，不访问凭据模块；后台更新由组合层注入，在预演与校验通过后触发。contract、state、shared 分别持契约、凭据/意图及基础能力，不反向依赖入口或业务执行。架构检查验证实际模块边与外部 SDK 所属；模块间不新增转发接口或工厂。
parser 归命令树所有；schema 负责投影和发现，契约查询直接使用 ContractCatalog。批量执行复用全部预校验后的请求，不重复读取正文；发送上传前仍核对原文件摘要。

2026-10-12 复核补充：CLI、批量与 MCP 共享失败分类；远端损坏 JSON 属于响应故障，不是用户输入错误。没有方法且没有显式 help/version 的调用返回输入错误并提供命令示例。显式 invocation ID 在预演及凭据访问前校验。HTTP 408/429 和 409 idempotency_request_in_progress 不构成已确认业务拒绝，不得将其缓存为永久 rejection；恢复仍使用原请求、原键与既有窗口，未知无键写入继续拒绝重放。
代码精炼：CommandTree 只负责语法与发现，ControlCall 统一入口，ControlOperations 负责预演、确认和执行，MCP/批量不创建命令解析器。更新检查、安装和回滚保留独立进程运行，在一个 UpdateProcess 入口中分派。生产代码的中文注释解释职责、执行顺序及安全约束，供初学者按调用链阅读。
Aesh 3.18.5 负责非交互命令解析和类型绑定；固定命令与动态 API 使用同一实际命令模型，schema 从该模型投影。命令层统一路由 help/version、输出和错误，保留业务命令路径、退出码及脱敏边界；不启用交互提示或 shell 操作符。运行依赖只保留 Aesh 与解析/help 所需的 terminal-api 3.18.6，排除 readline、readline-api、terminal-tty、terminal-detect；恢复交互能力前必须重新评估依赖及回归。动态 API 仍按需加载契约，共用执行器不依赖解析结果。禁止框架默认错误处理回显不可信输入或秘密。历史迁移结果保留为证据，当前版本按现行规格验证机器契约和真实行为，并以同 JDK 的交错独立进程样本报告端到端性能，help 排版允许框架差异。
技能采用一个自包含的中文入口，通用指导、当前契约与本次事实保持分工。保留任务顺序、必要示例、分支约束与完成条件，完整参数以当前 help/schema 为准。安装只更新当前受管技能；以持久所有权清单清理其过期受管文件，兼容本安装器原先的标记和五个已知附属路径，保留无关文件和其他技能。只读 --check 检出过期受管文件，安装前拒绝受管路径内的符号链接及非法所有权路径，验证全部目标后才写入，不新建备份。技能验证包含结构、链接、实际 CLI 发现与预演，以及 Pi 隔离真实业务场景的行为和 token 对照。

命令采用 `control resource method`，参数与正文使用 `--params` / `--json`。逐层 --help 与点分 schema 方法/类型提供运行时内省；知识精炼进 description，无单独本体、规则或 IO 主题树。
唯一 wire/type/auth 来源为生成 OpenAPI，独立 JSON 元数据补命名和说明；所有命令覆盖/排除必须完整。当前实现使用发行物内的契约快照，更新经签名发布交付；不增加远程 Discovery 服务。
跨平台生成使用 UTF-8 与 LF。Git 保留 OpenAPI 的 LF 字节，以固定契约哈希；生成目录的索引统一使用 `/`，不随宿主路径分隔符变化。
进程 stdout/stderr 使用 UTF-8，不随 Windows 控制台编码变化。更新目录须属于当前用户；用户目录的所有者不作为身份依据。解包的新目录沿用已验证安装目录的所有者。
更新子进程失败时记录固定阶段和异常类型，不回显原始异常消息。
API 成功直接输出 JSON，错误 JSON 在 stdout，诊断在 stderr；format 负责展示，output 负责文件。部分响应由后端 fields 实现，NDJSON 每行一页且有界。
HTTP 协商保留 JSON 优先级，并接受服务端声明的其他媒体类型。ZIP、CSV 等下载不得因客户端写死 Accept 列表而返回 406。
批量记录和 MCP 元数据保留 HTTP 状态；202 表示已受理。批量 completed 仅统计返回的命令调用，不证明后台业务完成。
无交互路径覆盖全部输入；秘密使用预配置引用或受保护 stdin/文件。拒绝注入与类型错误，合法正文保真。dry-run 无业务和私密恢复状态副作用。
敏感字段按名称与值类型统一识别：password/secret/token 后缀和上传签名 URL 默认脱敏，包括账户密码、邀请凭据与嵌套结果；token 元数据对象保留 ID、scope 等公开字段。预演始终脱敏，MCP 不暴露秘密生命周期方法。schema 必须展示所有已声明的成功响应类型，包括通配媒体类型和二进制类型。
即使响应契约遗漏秘密能力标记，已识别的秘密字段仍默认脱敏。方法 schema 同时公开请求媒体类型，避免把 multipart 上传误解为直接发送文件自身 MIME。
CLI、MCP、批量共用校验/执行；MCP 固定身份和文件根，默认只读。高影响确认不代替服务端授权。幂等/强 ETag/加密回执限制重复效果，未知无键写入拒绝重放。
删除旧 schema show/ontology/help topics、扁平字段 flags、旧结果信封与旧分页协议；不留同功能双实现。已有凭据配置不删除，安全状态存储继续按真实身份/请求校验。
新 CLI 主版本为 1，旧自动更新不能静默跨主版本。签名更新与业务凭据隔离，保留验证失败回滚。
